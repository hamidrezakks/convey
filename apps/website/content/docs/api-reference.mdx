# REST API Reference

Convey exposes an **OpenAPI 3.1-compliant REST API** served via Elysia.js on port `3000`.

---

## Authentication & Base URL

All requests must include an API Key in the `Authorization` header:

```http
Authorization: Bearer cv_live_your_api_key_here
```

| Environment | Base URL |
| :--- | :--- |
| **Local Development** | `http://localhost:3000/v1` |
| **Production VPC / Internal Gateway** | `https://api.convey.internal/v1` |
| **Interactive Swagger UI** | `http://localhost:3000/swagger` |

---

## Standard Error Response Schema

All error responses from Convey return an RFC 7807-compliant JSON body:

```json
{
  "code": "ERR_RATE_LIMITED",
  "message": "Tenant rate limit exceeded for quantum tier.",
  "details": {
    "tier": "FREE",
    "currentRps": 25,
    "limitRps": 10,
    "retryAfterMs": 1250
  },
  "traceparent": "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01",
  "timestamp": "2026-08-24T19:50:00.000Z"
}
```

### Standard Error Codes Dictionary

| Error Code | HTTP Status | Description | Action Required |
| :--- | :--- | :--- | :--- |
| `ERR_INVALID_PAYLOAD` | `400 Bad Request` | Missing required fields or schema validation failed | Correct payload schema |
| `ERR_UNAUTHORIZED` | `401 Unauthorized` | Missing or invalid Bearer API key | Pass valid `cv_live_...` key |
| `ERR_FORBIDDEN` | `403 Forbidden` | API key lacks permission for team or route | Check key workspace scope |
| `ERR_MESSAGE_NOT_FOUND` | `404 Not Found` | Specified `msg_<ULID>` was not found | Verify message identifier |
| `ERR_IDEMPOTENCY_CONFLICT`| `409 Conflict` | Same key submitted with differing payload | Use unique idempotency keys |
| `ERR_RATE_LIMITED` | `429 Too Many Requests`| Token bucket rate limiter or DRR quantum exceeded | Backoff and retry with jitter |
| `ERR_CIRCUIT_OPEN` | `503 Service Unavailable`| All downstream providers in fallback chain are OPEN | Wait for canary self-healing |

## 1. Send Single Message

`POST /v1/messages/send`

Ingests a single notification message into the fast-path pipeline with synchronous `202 Accepted` response.

### Headers

| Header | Required | Description |
| :--- | :--- | :--- |
| `Authorization` | **Yes** | `Bearer cv_live_...` |
| `Content-Type` | **Yes** | `application/json` |
| `Idempotency-Key` | Recommended | Unique key to guarantee single-execution semantics |
| `traceparent` | Optional | W3C Distributed Tracing header (`00-<32hex>-<16hex>-01`) |

### Request Body Schema

```json
{
  "channel": "sms",
  "recipient": "+14155552671",
  "priority": "HIGH",
  "content": {
    "body": "Your verification code is 849201. Valid for 10 minutes."
  },
  "routing": {
    "strategy": "SMART_SCORECARD",
    "fallbackChain": ["twilio", "vonage", "infobip"],
    "retry": {
      "maxAttempts": 3,
      "backoff": "FULL_JITTER",
      "initialIntervalMs": 500,
      "maxIntervalMs": 3000
    }
  },
  "metadata": {
    "userId": "usr_9921",
    "campaign": "security_auth"
  }
}
```

## 2. Bulk Message Ingestion

`POST /v1/messages/bulk`

Ingests up to 1,000 messages in a single atomic transaction:

```json
{
  "channel": "email",
  "priority": "LOW",
  "messages": [
    {
      "recipient": "user1@domain.com",
      "content": { "subject": "Product Update", "body": "Hello User 1" },
      "idempotencyKey": "bulk_u1_20260824"
    },
    {
      "recipient": "user2@domain.com",
      "content": { "subject": "Product Update", "body": "Hello User 2" },
      "idempotencyKey": "bulk_u2_20260824"
    }
  ],
  "metadata": {
    "campaignId": "newsletter_august_2026"
  }
}
```

### Response (`202 Accepted`)

```json
{
  "batchId": "batch_01JB61ZZ89901AA223344",
  "status": "ACCEPTED",
  "totalSubmitted": 2,
  "totalAccepted": 2,
  "totalRejected": 0,
  "latencyMs": 4.82,
  "createdAt": "2026-08-24T19:50:00.000Z"
}
```

## 3. Query Message Status & Tracing

`GET /v1/messages/:id`

Retrieves the lifecycle delivery status, carrier timeline, and W3C distributed trace waterfall for a message:

```bash
curl -X GET http://localhost:3000/v1/messages/msg_01JB61Z89F8A3C1E2B4D5E6F77 \
  -H "Authorization: Bearer cv_live_demo_key"
```

### Response (`200 OK`)

```json
{
  "publicId": "msg_01JB61Z89F8A3C1E2B4D5E6F77",
  "status": "DELIVERED",
  "channel": "sms",
  "recipient": "+14155552671",
  "priority": "HIGH",
  "provider": "twilio",
  "traceparent": "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01",

    {
      "attempt": 1,

    }

  "createdAt": "2026-08-24T19:50:00.000Z",
  "deliveredAt": "2026-08-24T19:50:01.142Z"
```

## 4. Dead-Letter Queue (DLQ) & Mutated Replay

`GET /v1/dlq` — Query dead-letter messages with root-cause clustering.

`POST /v1/dlq/replay` — Execute dry-run or live replay with mutated routing:

```bash
curl -X POST http://localhost:3000/v1/dlq/replay \
  -H "Authorization: Bearer cv_live_demo_key" \
  -H "Content-Type: application/json" \
  -d '{
    "since": "2026-08-24T00:00:00.000Z",
    "failureReason": "PROVIDER_RATE_LIMIT_429",
    "dryRun": false,
    "overrideRouting": {
      "strategy": "SMART_SCORECARD",
      "rateLimitRps": 50
    }
  }'
```

## 5. Suppression Lists

`GET /v1/suppressions` — List suppressed recipient addresses (hard bounces, spam complaints).

`POST /v1/suppressions` — Manually add an address to the global suppression list:

```bash
curl -X POST http://localhost:3000/v1/suppressions \
  -H "Authorization: Bearer cv_live_demo_key" \
  -H "Content-Type: application/json" \
  -d '{
    "recipient": "bad_email@invalid-domain.xyz",
    "channel": "email",
    "reason": "HARD_BOUNCE"
  }'
```

## 6. Health & Readiness Probes

| Endpoint | Method | Purpose | Response |
| :--- | :--- | :--- | :--- |
| `/health` | `GET` | Overall subsystem status | `{"status":"ok","version":"1.0.0"}` |
| `/health/readiness` | `GET` | Kubernetes readiness probe (PostgreSQL 18 + DragonflyDB) | `{"ready":true,"checks":{"db":"connected","redis":"connected"}}` |
| `/health/liveness` | `GET` | Kubernetes liveness probe | `{"alive":true}` |
| `/metrics` | `GET` | Prometheus telemetry metrics scrape endpoint | Text/plain Prometheus format |
