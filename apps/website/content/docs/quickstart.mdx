## Prerequisites

Use Bun `1.4.0` (the repository's `.bun-version`), PostgreSQL 18, and a Redis-compatible service such as DragonflyDB. Docker Compose is optional. Convey is pre-release: initialize a fresh disposable database and queue namespace when the canonical schema or persisted queue format changes.

## Start the API locally

```bash
git clone https://github.com/hamidrezakks/convey.git
cd convey
bun install --frozen-lockfile
cp .env.example .env
```

Set `DATABASE_URL` and `REDIS_URL` in `.env` to your running services. `POSTGRES_DB`, when set, overrides the database path in `DATABASE_URL`. The example includes legacy mock provider values; current adapters use explicit database-backed provider configuration rather than automatically reading those variables. Configure a provider through the console or administration API for real delivery.

```bash
bun run db:check
bun run db:migrate
bun run dev:server
```

The API and background workers start together. There is no separate worker command. Confirm the listener and bootstrap state:

```bash
curl --fail http://localhost:3000/health/liveness
curl --fail http://localhost:3000/health/readiness
```

## Provision a team credential

Authentication is enabled by default. Through your database administration tool, create an active tenant in the initialized database. For a disposable local setup:

```sql
INSERT INTO tenants (id, name, status)
VALUES ('local-tenant', 'Local development', 'active');
```

In another terminal at the repository root, create a tenant credential:

```bash
bun apps/server/scripts/create-api-key.ts local-tenant local-team application DEVELOPER tenant production
```

The database trigger registers `local-team` to `local-tenant`. Teams are globally unique across tenants; choose a new team name if it already belongs to another tenant. The command prints an `sk_live_` secret once and stores only its hash. Keep the secret outside source control and set `CONVEY_API_KEY` in your terminal to the printed value.

The final argument selects the credential's environment. Use `sandbox` to create an `sk_test_` key; sandbox-only keys use `/v1/sandbox` APIs. The `production` argument above creates a credential for the regular API even when the local server uses `NODE_ENV=development`.

## Accept your first message

Configure an implemented provider for delivery using the operator console or the platform administration API. Review [providers](/docs/providers) before choosing an integration. Acceptance records a message; it does not confirm delivery.

```bash
curl --fail-with-body -X POST http://localhost:3000/v1/messages   -H "Authorization: Bearer $CONVEY_API_KEY"   -H 'Content-Type: application/json'   -d '{
    "idempotencyKey": "quickstart-sms-001",
    "userId": "local-user",
    "team": "local-team",
    "category": "transactional",
    "country": "US",
    "priority": "normal",
    "recipients": { "phone": "+14155552671" },
    "channels": [
      { "channel": "sms", "content": { "text": "Hello from Convey" } }
    ]
  }'
```

Replace the sample phone with your test recipient before sending through a real provider. `team` must match the credential's team, and `idempotencyKey` belongs in the JSON body. A first acceptance returns `202` with this shape:

```json
{
  "messageId": "msg_01K4N7GZQZ0000000000000000",
  "state": "accepted",
  "createdAt": "2026-10-10T10:00:00.000Z"
}
```

Use the returned `messageId` to poll `GET /v1/messages/:messageId` with the same credential. SDK clients also need an explicit base URL and the matching team; see [SDKs](/docs/sdks). To send user IDs through recipient resolution, see the [Go gateway](/docs/gateway).

## Start the operator console

Create a separate platform credential for administration:

```bash
bun apps/server/scripts/create-api-key.ts local-tenant local-team operator ORG_ADMIN platform production
```

Run each service in its own terminal:

```bash
bun run dev:plugins
bun run dev:web
bun run dev:website
```

Sign into the console with the platform key. The console keeps the key in tab memory and clears it on reload or sign-out. Platform credentials permit privileged administration; keep them out of client applications.

| Service | Default local address | Check or purpose |
| --- | --- | --- |
| API | `http://localhost:3000` | `/health/liveness`, `/health/readiness`, `/health` |
| OpenAPI UI | `http://localhost:3000/swagger` | API reference |
| Operator console | `http://localhost:5173` | Platform-key sign-in |
| Optional plugins | `http://localhost:3001` | `/health`; proxied by the console |
| Documentation | `http://localhost:5174` | `bun run dev:website` |

## Docker evaluation

The checked-in Compose stack builds local images and includes provider simulation, development credentials and exposed infrastructure ports. Follow [deployment](/docs/deployment) to set container-network connection URLs, secrets and authentication. It is an evaluation setup, and signed callback verification may reject unsigned simulator callbacks.

For an isolated non-production experiment only, `CONVEY_REQUIRE_AUTH=false` enables the development bypass. Production rejects this setting. Prefer the authenticated setup above.
